# ADR-0015 段階 1 で docs の記述から外れた判断

日付 2026-09-13 / 状態 採用

## 問題

段階 1 の本体 (配色・四分位・凡例) を実装するにあたり、design §7 には式の骨格と定数表があるが、
実装に要る細部の多くが書かれていなかった。多くは慣習どおりに決めて design §7 に書き足したが、
**docs の文言どおりに実装すると壊れる箇所**があり、そこは文言から外れる判断をした。

## 決定 1 — 四分位の母集団からデッドゾーン未満の日も外す

design §7 は「0 の日を母集団から除外」と書いていた。**0 の日だけでなく、合計がデッドゾーン (3 分)
未満の日も外す。**

文言どおりだと、`<=` で防いだはずの「全マス Level 4」が再発する。20 秒ポーリングで 1〜2 分の日は
多く出るので、それらが母集団に残ると四分位が小さい値に潰れる。

| 母集団 | 0 だけ除外 | デッドゾーン未満も除外 |
|---|---|---|
| [1,1,2,2,3,30,60] | 四分位 1.25/2/2.75 → 3・30・60 が**全部 Level 4** | 16.5/30/45 → 3→1、30→2、60→4 |
| [1,1,1,1,2,2,2,5,8,20] | 1/2/2 → **全部 Level 4** | 6.5/8/14 → 5→1、8→2、20→4 |

デッドゾーン未満の日はどうせ Level 0 で表示されるので、母集団から外して困る場面は見つからなかった。
**デッドゾーンを変えると母集団も変わる**ので、定数は `MIN_MINUTES` の 1 つにまとめてある
(段階 7 で決めるときに一緒に動く)。

## 決定 2 — ETag は本文の SHA-256 にする

design §6 は「ETag は `users.ver` と描画パラメータから作る。日付は入れない」と書いていた。
**本文の SHA-256 にする。**

文言どおりだと、**配色やレイアウトを直してデプロイしても、キャッシュを持つ側に 304 が返り続け、
古い画像が残る。** 鍵に描画コードの版が入っていないため。304 のたびにキャッシュの寿命が延びるので、
いつまでも直らない。

描画の版を鍵に足す手もあるが、手で上げる定数は上げ忘れる。本文から作れば描画が変わったときだけ
変わり、常に正しい。SVG 1 枚のハッシュは安い。

段階 3 で実データを描くときにも効く。今日の列が右端なので日付が進めば本文が変わるが、
文言どおりの鍵 (`users.ver` と描画パラメータ) では**活動の無い期間ほど 304 で格子が止まる。**
本文のハッシュならこれも起きない。

## 帰結

- **ETag を計算するには描画しなければならない。** 304 で本文の生成を省けない。
  SVG 1 枚は数 ms で、Workers Cache を有効にすればヒット時は Worker を実行しないので問題にならない
- 導入直後の 1 日目は Level 1 (最も淡い) になる。値の違う日が 2 日目に来ると四分位が開き、
  多い方の日が Level 4 に跳ねる。design §16 の「今日大量に書くと去年のマスが薄くなる」と同じ性質
- design §7 に書き足した他の細部 (フェンスを `<=` で残す、center はフェンスの前、母集団が空なら +∞、
  二分探索の手順) は文言から外れていないので ADR にしない。design §7 が正本
