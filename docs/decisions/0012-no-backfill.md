# ADR-0012 バックフィルを実装しない

日付 2026-09-12 / 状態 採用。ADR-0004 を置き換える

## 問題

ADR-0004 で「commits が残っている直近 30 日だけ遡る」と決めた。実装の費用対効果を見直した。

得られるもの。最大 1 か月分の書き込み記録。read は原理的に 0。

必要なもの。1000 ページのページ一覧取得、各ページの commits 取得 (並列度 5・インターバル 200ms で
数分)、リネームカスケードの除外、進捗表示、中断と再開。

## 決定

**実装しない。** 導入日から記録を始める。

## 帰結

**設計が一段簡単になる。** 次のものが全部消える。

- `daily.backfilled` カラム
- 四分位スケールの母集団から `backfilled` を除く例外処理
- 色相の `center` の母集団から `backfilled` を除く例外処理
- バックフィル日と計測日の境界線の描画
- `/api/commits` を叩くコードと、そのレート制限への配慮

代償は**導入直後の草が空になる**こと。グラフの左端に「ここから計測開始」と出して、
データがないことと活動がなかったことを区別する。

## 記録として残すもの

`research.md` の `/api/commits` の調査結果は消さない。「30 日で消える」という事実が
この判断の根拠であり、将来気が変わったときに再検証の起点になる。

ADR-0004 のリネームカスケード対策 (`changes` が `LinksChange` / `IconsChange` / `TitleChange`
だけの commit を除外する) も、将来バックフィルを作るなら再利用できるので残す。
