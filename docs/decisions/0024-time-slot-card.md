# ADR-0024 ページカードのサムネ向けに、曜日 × 時間帯の草と 4 軸の線を 1 枚にした図を足し、時間帯の内訳を暦の日ごとに 4 区間で持つ

**2026-10-07、Issue #208。** 実装は段階 10 (roadmap) で、この ADR を書いた時点では未実装。

## 文脈

- Cosense のページ一覧はカードの格子で、ページの最初の画像がカードのサムネになる (research §3)。
  **今の草 (775 × 146) をサムネにすると、枠の上端の細い帯にしかならない** (幅 143px に縮むので高さ 27px)。
  活動の概観 (300 × 220、ADR-0021) は別の画像なので、1 枚のサムネには草か概観のどちらかしか出ない
- サムネの枠は 1 行のタイトルで幅 ÷ 高さが 1.08〜1.22 で、広い画面では約 145 × 122px。**画像は枠の幅に合わせて上端をそろえ、
  はみ出した下を切る** (research §3 の 2026-10-07 の実測)。タイトルが 2 行なら 5:4 の画像の下 12%、3 行なら 29% が切れる
- ページの本文では画像は `max-height: 300px` で出る (research §3)
- 記録は日ごとの合計 (`daily`) と、90 日で消える分単位のビットマップ (`daybits`) だけで、**時間帯の内訳は永続していない**。
  ビットマップの分は端末のローカル時刻の 0:00 からの分 (design §4)
- この図は**利用者が別に作るページのサムネに使う**ことを狙う (Issue #208 の 2026-10-07 の確認)。プロフィールページへの自動挿入 (ADR-0025) は
  「必ずどこかに表示される」ための仕組みで、そちらのページのサムネになっても困らない

## 決定

### 1. 時間帯は 朝 9–13 / 昼 13–18 / 夜 18–9 の 3 つで、夜は「その日の夜」

- 夜は D 18:00〜D+1 9:00 を D の夜とする。深夜 0 時を過ぎた作業を前の日に数える方が、生活の 1 日として読める
- 時刻は記録と同じく**端末のローカル時刻**。サーバはタイムゾーンを持たない (今の草と同じ)

### 2. 保存は暦の日ごとに 4 区間 (0–9 / 9–13 / 13–18 / 18–24) で持ち、夜は描くときに組み立てる

- `daily` に `sw0..sw3` (区間ごとの書いた分) と `sr0..sr3` (区間ごとの読んだだけの分 = `r & ~w`) を足す。境界は分で `[0, 540, 780, 1080, 1440]`
- **夜は描くときに `D の区間 3 + D+1 の区間 0` で組み立てる。** 夜を 3 区間目として保存すると、D の夜を確定するのに D+1 のビーコンが要り、
  受け口が受け取った日とは別の日の行を書くことになる。暦の日ごとに持てば、受け口は今と同じく受け取った `(ph, day)` の行だけを書く
- **ビーコンは変えない。** 受け口がマージした後の `wbits` / `rbits` から区間ごとに数える。ビットマップは毎回全量届く (ADR-0002) ので、新しい項目を送らせなくてよい
- 端末をまたいだときは、区間ごとに今の `w` と合計と同じ規則 (max) で守る (design §5)
- **NULL は「内訳なし」。** 列を足す前の日は NULL のままで、`daybits` が残っている 90 日分は Cron が遡って埋める。それより古い日は内訳が戻らないので、
  図ではその日の合計の色を 3 マスに薄く塗る
- 区間の合計はその日の `w + r` に一致する (同じビットマップから数えるので)

### 3. 図の形

モックを 10 回ほど描き直して決めた (モックは会話の中の使い捨て。Issue #208 の 2026-10-07 のコメント)。

**キャンバスとラベル**

- 500 × 400 (5:4)。背景は透明で、`theme=dark` にも対応する
- ラベルは日本語が既定で、`?lang=en` のとき英語にする

**草**

- 正方形のマスで、列は週 (**26 週**)。行は曜日 (月〜日) × 時間帯 (朝 / 昼 / 夜) の 21 行
- **1 日 = 縦長のタイル**: 3 マスを細い切れ目だけでつなぎ、上下の角だけを丸める。日と日の間は縦横で均等に空ける
- マスの色は今の草と同じで、濃さは量、色合いは読み書きの釣り合い (design §7)
- **空きマスは朝 → 昼 → 夜の順に灰色が少しずつ濃くなる** (朝昼夜をさりげなく示す)
- 左に曜日を置く (土日は一段淡く)。上に月を置く (淡く)
- 右端に「計」の列を置き、曜日 × 時間帯ごとの期間の合計を灰色の濃淡のタイルで示す

**4 軸 = 草の下の 1 本の線**

- 額縁は無い。草の下に、草の左端から「計」の列の右端までの線を 1 本引く
- 線を「作る / 育てる / 関わる / 読む」(ADR-0021) の 4 区間に分け、**全体に対する割合**で長さを取り合う (無段階)。区間の間は小さく空ける
- 色は 4 段階の灰色 (濃 → 淡)。ダークテーマでは濃淡を逆にする
- 軸の名前は、各区間の左端の下に**ごく小さく淡く**置く (草のラベルより一段控えめにする)。名前を書く幅が足りない区間では名前を省く
- 0 分の軸は区間を作らない。4 軸すべてが 0 なら、淡い 1 本の線だけにする

**名前の行 (下)**

- 左から `/プロジェクト名` (太字)、Cosense のアイコン (丸く切り抜く)、ユーザー名 (控えめ、`@` なし)
- 合算の図では、プロジェクト名の代わりに既存の合算の印 (`layout.ts` の `layoutMark`) を置き、アイコンは入れない (どのプロジェクトのアイコンを使うかが決まらない)
- 名前は `?l=` / `?u=` で受け取り、サーバには保存しない (ADR-0007。今の草と同じ)
- **時間帯の凡例は置かない** (朝昼夜は空きマスの濃淡だけで示す)

**実寸の制約**: カードでは 1 マスが約 4px で、ラベルは読めない。ラベルはページの本文の表示 (高さ最大 300px) で読める大きさにする。
カードで読めるのは、色の分布 (いつ活動しているか) と線の割合だけでよい。

### 4. 置き場は `/v1/g/{publicId}/card.svg` で、今の草と概観の SVG は 1 バイトも変えない

- 草と同じ `publicId` から作る (概観と同じ判断。ADR-0021 決定 6)。草の URL を受け取った人は、末尾を変えるだけでカードも見られる
- 草と概観を変えないので、ゴールデンテスト・ETag・README の画像の台帳はそのまま保たれる
- 受けるクエリは `lang` / `l` / `u` / `theme`。応答のキャッシュと ETag は草と同じ (`public, max-age=900`)
- SVG の中でもプロジェクト名に `<a href>` を埋める (SVG を直接開いたときに効く。research §3)

### 5. アイコンは Worker が取得し、`data:` の URI で埋め込む

- 取り先は `https://scrapbox.io/api/pages/<l>/<u>/icon` (`[user.icon]` と同じもの。research §4)。
  **`<img>` で読まれた SVG は外部の画像を読まない**ので、URL を書くのではなく中身を埋め込む (実機の確認は図の PR で行う。research §7)
- 転送を辿る先は `gyazo.com` / `i.gyazo.com` / `scrapbox.io` / `storage.googleapis.com` に限る。種類は png / jpeg / gif / webp だけで、SVG は入れない。大きさに上限を設ける
- 結果は失敗も含めて Cache API に置く (例: 成功 1 日、失敗 1 時間)。**D1 には保存しない**
- **取れないとき (非公開プロジェクト・404・失敗) はアイコンを出さず、名前だけにする**
- **Google のアイコンは使わない。** `profile` のスコープと保存が要り (今は `openid` だけ。ADR-0011)、Google アカウントの顔が公開されるため
- カードのレスポンスの CSP にだけ `img-src data:` を足す (草と概観のヘッダは変えない)

## 却下した案

- **草とレーダー (概観) を上下や左右に並べる。** 5:4 の中で両方を並べると、マスが小さくなるか、どちらも中途半端な大きさになる
- **レーダーを草の背面に重ねる。** 重なったところでどちらも見にくい
- **時間帯ごとに帯を分ける** (上に朝の 7 行、中に昼の 7 行、下に夜の 7 行)。**1 日が 3 か所に分かれ**、同じ日の朝と夜を見比べにくい
- **1 日のマスを 3 分割し、右にパンチカード (曜日 × 時間帯の集計) を置く** (案 N)。パンチカードに幅を取られて**草が 13 週に縮み**、下に余白も残る
- **4 軸を画面の 4 辺のバーにする** (最初に採った案 M。今のレーダーと同じ位置に割り当てていた)。紫のバーは目立ちすぎ、
  灰色にしても「ぱっと見は枠、よく見ると割合」の額縁 (一続きの額縁の一部を濃くする) と目盛りまで試したうえで、
  **作者が「1 本の線を 4 つで取り合う」形を選んだ。** 4 本が別々の辺にあると長さを同じ基線で比べられず、
  全体に対する割合は 1 本の線を分ける方が直接に読める。辺の中央に置いた軸名が額縁の切れ目に見える問題もあった
- **4 軸の線を色で塗り分ける** (読む = 紫、書く 3 軸 = 琥珀)。作者が目立ちすぎると判断した。
  草のマスの色 (濃さ × 読み書き) と並ぶと色が 2 つの意味を持つことにもなるので、線は灰色の濃淡にし、色は草だけが使う
- **1 日ごとに台座を敷く。** 囲みははっきりするが線が増えて賑やかになる。3 マスを細い切れ目でつないだ縦長のタイルで、
  要素を足さずに 1 日のまとまりを示せる
- **時間帯の凡例** (日の出・太陽・三日月のアイコンと時刻) を名前の行に置く。作者が不要と判断した。
  カードの寸法では読めず、朝昼夜は空きマスの濃淡でさりげなく示せば足りる

## 帰結

- **カードのサムネが切れても、大事な情報が残る。** 草と線を上に寄せ、名前の行を下端に置いたので、タイトルが 2〜3 行で下が切れても名前の行が欠けるだけで済む
- 草の URL を受け取った人には、**直近 26 週の日ごとの時間帯の活動**もカードとして見える (決定 4)。プライバシーポリシーに書いた
- アイコンの取得は Worker から scrapbox.io への外向きのリクエストになる。取り先と転送先を許可リストに限り、結果をキャッシュして回数を抑える
- `daily` の 1 行が整数 8 個ぶん大きくなる (design §11 の容量の見積もり)。Cron が遡って埋める行は 1 回あたりの上限で書き込みの予算を守る
- 実装は 3 つに分ける: 区間の集計 (受け口・D1・Cron) → 図 (`card.svg`) → UserScript (ADR-0025 と、ダイアログのカード)

## 2026-10-08 の改訂 — カードを基本形にして、草と概観を同じ描画にまとめる (ADR-0026、Issue #220)

段階 11 で実装する。

- **決定 4 (草と概観の SVG は 1 バイトも変えない) を上書きする。** 草 (`{publicId}.svg`) はカードと同じ描画の「1 年 × 1 日」を既定として返し、
  概観 (`overview.svg`) は廃止してカードの既定を返す
- **決定 3 の「列は週 (26 週)」と決定 4 の「受けるクエリは `lang` / `l` / `u` / `theme`」を広げる。**
  `span` (半年 / 1 年)・`cell` (3 分割 / 1 日)・`year`・`mode`・`palette` も受ける。既定 (半年 × 3 分割、500 × 400) は変えない
- **決定 3 の 4 軸の線に、% の数値をごく小さく添える** (ADR-0026 決定 5)。計測開始前の日には点線の枠を描く
- **決定 5 の「カードのレスポンスの CSP にだけ `img-src data:` を足す」を、図を返すすべての経路に広げる**
- プロフィールページに自動で貼る行 (ADR-0025) は、クエリなしの `card.svg` のまま変えない

## 2026-10-08 の改訂 — 前日の行が無くても 0–9 時の分を夜に入れる (Issue #230)

**決定 2 の「夜は描くときに `D の区間 3 + D+1 の区間 0` で組み立てる」を、D の行が無い日にも広げる。** D に活動が無く行が無いと、
組み立てる先が無いので D+1 の 0–9 時の分が図にも四分位の母集団にも JSON (ADR-0020) にも出なかった。

- D の行が無く、D+1 の区間 0 に分があれば、D を「朝 0・昼 0・夜 = D+1 の区間 0」の日として描く。計測開始日の前日でも塗る (3 分割の形だけ。1 日 1 マスは暦の日の合計なので点線の枠のまま)
- D の行があって内訳なしの日は今までどおり。そこへ入るはずの D+1 の 0–9 時は落ちるが、内訳なしの最後の日の 1 晩に限られる
- 受け口と保存は変えない。描くときの組み立て (`slotsOf`) だけを直す
