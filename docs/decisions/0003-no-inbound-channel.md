# ADR-0003 受信方向は当面作らない

日付 2026-09-12 / 状態 採用

## 問題

指示書 §6.7 は DOM 注入版の草を `GET /v1/g/{publicId}.json` で取得する前提だった。
`fetch` が使えないので取得できない。

## 決定

**この決定は ADR-0019 で取り消した** (草を描くのは Worker だけになった)。以下は当時の記述。

DOM 注入の草は **localStorage に持つ日次集計から描く**。自分のデータは自分のブラウザにあるので、
サーバに問い合わせる必要がない。ツールチップもインタラクションも作れる。

複数デバイスを統合した草を見たいときは、共有 SVG (`<img>`) を見る。これは非インタラクティブ。

`/v1/g/{publicId}.json` はエンドポイントとして実装しておくが、UserScript からは使わない。

## 帰結

localStorage に日次集計 (53 週分の `w` / `r` / `pages` / `created`) を保持する必要がある。
371 日 × 4 値で JSON 約 15KB。localStorage の 5MB に対して問題ない。

これは ADR-0001 で却下した「Cosense をストレージにする」案への移行もしやすくする。
ローカルの日次集計をそのまま書き出せばよい。

## 将来の選択肢

受信方向が本当に必要になったら、CORS 画像と canvas のピクセル読み出しで実現できる。
`img.crossOrigin = "anonymous"` を `src` より前に設定し、Worker が `Access-Control-Allow-Origin` を
返せば canvas が tainted にならず `getImageData()` できる。CSP では `img-src` の管轄のまま通る
(effective directive は request の destination で決まるため)。

371 日 × 4 値なら 1.5KB 程度なので画像 1 枚に十分載る。

## 2026-09-12 の改訂 — 複数デバイスで穴になった

**ADR-0019 で取り消した** (このブラウザの記録から描く草そのものが無くなった)。

DOM 注入版は localStorage から描くので、**そのデバイスで観測した分しか持たない**。
複数デバイスを使うと「PC では PC の活動しか見えない」ことになる。

「草を見る」に 2 つの表示を置くことにした。

- **このブラウザの記録** — localStorage から描く。ツールチップ付きでインタラクティブ
- **統合された記録** — 共有 SVG を `img` で埋め込む。非インタラクティブだが全デバイス分

実装は `img` タグ 1 つで済む。受信方向を作らない判断はそのまま維持する。

なお**サインインのポップアップは例外的に双方向になる**。CSP は `postMessage` を妨げないので、
ポップアップから `window.opener.postMessage` で識別子を受け取れる (ADR-0011)。
ただしユーザー操作が必要なので、定期的なデータ取得には使えない。

## 2026-09-15 の改訂 — ページに挿さず、ダイアログで見せる

「草を見る」(段階 8、Issue #73) を作るときに 2 つ決めた。

**1. 草はページに挿さず、ページメニューから開く `<dialog>` に出す。**
ページに挿すと Cosense の遷移で要素が消えるので、`page:changed` / `layout:changed` で再マウントと後片付けが要る
(research §2「常駐」)。ダイアログは押したときに作って閉じたら消すので、どちらも要らない。
`showModal` はページを inert にするので、開いている間に遷移も起きない。
ページの中に常に草を置きたくなったら、そのときに再マウントを作る。

**2. 草は常にライトで出す。**
当初は「テーマは `document.documentElement` から判定する」だったが、素の `<dialog>` は Cosense のどのテーマでも
白地に黒で出る (research §3、2026-09-15 の実測。Cosense の CSS が装飾するのは `dialog.modal` だけ)。
ページのテーマに合わせて暗い草を出すと、白いダイアログの上で読めなくなる。
ダイアログの色をテーマに合わせるときは、ダイアログの背景色を読んで草のテーマを選ぶ (#81)。

## 2026-09-15 の改訂 — 統合の草を主にし、このブラウザの記録は内訳に降ろす

**ADR-0019 で取り消した。** ここで「消さない」と書いた 2 つの理由 (ツールチップと、未登録で見られる
唯一の草) は、どちらも**そのまま失うことを受け入れる**判断に変わっている。

2026-09-12 の改訂で置いた 2 つの表示を、**対等な節として並べていたのをやめる** (Issue #101)。

どちらも合算とプロジェクト別を並べるので、同じ形の草が最大 12 枚縦に並ぶ。
しかも 2 つは**必ず違う値になる** — このブラウザの記録は送信を待たずに増え、統合の方はほかの端末の分を含む。
主従が無いので「どちらが本当か」が読めなかった。

**統合の草を先に出し、このブラウザの記録は `<details>` に畳む。**

- **消さない。** ツールチップ (分数・ページ数) は共有 SVG には無く (§9)、未登録のときに見られる唯一の草でもある
- **統合の草を出せないとき (未登録・新しい版の鍵・保存領域が開けない) と、まだ 1 件も送れていないときは開いた状態で出す。**
  見るものがこれしか無いため
- **畳んでも中身は作る。** 今までも毎回描いていたので重くならず、`toggle` で作ると開いた直後の 1 フレームだけ空になる

これは**受信方向を作らない判断の帰結の扱い方**でもある。統合された記録は `img` でしか見られず、
ツールチップも差分も出せない。だから「主は絵として正しい統合の草、内訳はローカル」と役割を分ける。

**あわせてページメニューの名乗りを `cosense-grass` に変える** (それまでは「草を見る」)。
このダイアログは草を見るだけの場所ではなく、設定へ行く入口でもある。
ページメニューはほかの UserScript の項目と並ぶ場所なので、**動詞ではなく、どのスクリプトのものかが分かる名前**にする。
ダイアログの中の「草の設定」も、入れ子で指せるので「設定」に縮める。
