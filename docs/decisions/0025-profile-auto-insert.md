# ADR-0025 UserScript がプロフィールページにカードの図を貼り続ける。経路は同一オリジンの WebSocket で、ライブラリを使わずに書く

**2026-10-07、Issue #208。** 実装は段階 10 (roadmap) の UserScript の PR で、この ADR を書いた時点では未実装。
**commit が実際に受理されるかは、まだ確かめていない** (帰結)。

## 文脈

- カードの図 (ADR-0024) は、利用者が自分でページに貼らなければどこにも出ない。**導入した人の図が必ずどこかに表示される**ようにしたい
- 導入した人は、各プロジェクトの自分のユーザー名のページ (以下、プロフィールページ) に import の 1 行を書いている (design §9)。
  このページは必ずあり、UserScript もそのページの `code:script.js` から読み込まれる
- **UserScript はこれまでページに書いたことが無い。** 読むのは同一オリジンの REST、外へ出すのは画像 GET のビーコンだけ (ADR-0001)
- CSP の `connect-src` は `'self'` と `wss://scrapbox.io` を含み、ページの中から `wss://scrapbox.io/socket.io/` を開ける (research §1 の 2026-10-07)。
  本体はこの接続の上で socket.io-request の `commit` を送ってページを保存している。認証は Cookie だけで、CSRF トークンは要らない (research §4)
- 利用者はまだ作者だけ (ADR-0021 の文脈と同じ)

## 決定

### 1. 同一オリジンの WebSocket で、プロフィールページへ commit を送る

- 開いていないページにも書ける。`pageId` / 直前の `commitId` / 行の id / `projectId` / `userId` は REST で引く
- **ライブラリは使わず、ネイティブの `WebSocket` の上に Engine.IO v4 / socket.io v5 の最小限を書く。**
  やり取りは `0` (open) → `40` (名前空間に接続) → `42<ack>` で socket.io-request の `commit` → `43<ack>` で応答。
  サーバの ping (`2`) に pong (`3`) を返し、タイムアウトを付け、終わったら閉じる
- 理由は配布物の大きさ。minify しない今のバンドルが 115,745 B なのに対し、socket.io-client 4.8.4 は +116,459 B、
  @cosense/std 0.31.0 の `patch` は +181,164 B になる (research §4)。配布は minify しない (読めるコードを配る) ので、
  バンドルが倍以上になり、配布ページへの貼り付けが遅くなって 503 が増える (Issue #180)
- 普段は REST の GET 1 回で終わり、**WebSocket は貼るときだけ開く**
- ページのメタデータ (`linesCount` / `charsCount` / `image` / `descriptions`) の差分は、本体と同じくクライアントが計算して commit に入れる

### 2. 挿入する位置は「cosense-grass を読み込むコードブロックの最後の行の直後」

- そのコードブロックが無ければ最下部に置く。**最上部 (タイトルの直後) には置かない** — 利用者が書いた自己紹介を押し下げないため
- コードブロックの直後に置けば、導入の 1 行の近くに出るので、どの仕組みが貼ったものか見当が付く
- 図がページの最初の画像になってカードのサムネになっても困らない (Issue #208 の 2026-10-07 の確認)

### 3. 不変条件: insert だけを送り、コードブロックの外に入れる

- **既存の行は update も delete もしない。** 送る `changes` は `_insert` 1 つ (とメタデータの差分) だけ
- **コードブロックの中に入れない。** `code:script.js` の中に入ると配信される script.js が変わり、SHA1 の承認ゲート (research §2) で
  **UserScript そのものが止まる**。行は字下げしない (字下げした行はコードブロックの続きになる)
- この 2 つをテストで守る

### 4. 開くたびに確かめ、無ければ貼り直す。動かした行は戻さない

- プロジェクトを開いたとき (読み込みの送信の後と、登録に成功した後) に、REST でプロフィールページを読み、
  **そのプロジェクトの publicId を含む `…/card.svg` の行**があるかを見る。無ければ貼る
- 判定は URL の完全一致ではなく、`grass.soui.dev` / `cosense-grass.soui.workers.dev` の `card.svg` で、publicId が一致するかで見る
  (`l` / `u` や行の前後の文字を利用者が変えても貼り直さない)
- **利用者が動かした行はそのままにする。** 位置は最初に貼るときだけ決める
- **利用者が消したら、次に開いたときに貼り直す。** 止めるには UserScript (import の 1 行) を外す。これをプライバシーポリシーと README に書く
- 動く条件は、登録済み・Cosense にログイン済み・そのプロジェクトに導入済み (import の 1 行がある。ADR-0007 決定 5) のすべて

### 5. 二重貼りを防ぐ

- commit の `parentId` に読んだときの最新の commit を入れ、fast-forward でなければ (`NotFastForwardError`) 読み直して、行があるかを確かめ直す (最大 3 回)
- 同じブラウザのタブどうしは `navigator.locks` で直列にする

### 6. 貼る行はリンク付きの画像

```
[https://grass.soui.dev/v1/g/<publicId>/card.svg?l=<project>&u=<user> https://scrapbox.io/<project>/]
```

- 画像を押すとそのプロジェクトへ飛ぶ。サムネに選ばれるのは画像の側 (research §3)
- `l` / `u` は今の草と同じく画像に名前を描くためのもので、サーバは保存しない (ADR-0007)

### 7. 自動で貼った行は「書いた分」に数えない

UserScript が別の接続で送った commit は、開いているタブに `by: "remote"` で届く (research §4)。センサーは `edit` だけを数える (ADR-0006) ので、
**センサーを変えなくても数えない。**

### 8. 配布ページ `v1` を差し替える

UserScript の新しい機能は、本来は破壊的変更として新しい配布ページに分けるが (CLAUDE.md の「破壊的変更では配布ページを分ける」)、
**利用者がまだ作者だけなので、`dev` で確かめてから `v1` の中身を差し替える。** ADR-0021 の v2 ビーコンと同じ判断。

## 却下した案

- **socket.io-client / @cosense/std を依存に足す。** 決定 1 のとおり、バンドルが +116〜181 KB になる
- **編集画面の DOM を操作して行を足す。** 本体の入力として扱われ、`by: "edit"` で届いて**自分の書いた分に数えてしまう。** 開いているページにしか書けない
- **`scrapbox.Page.insertLine`。** Layout が `page` のときしか動かず (research §4)、プロフィールページを開いていなければ書けない。開くたびに確かめる (決定 4) を満たせない
- **公式の書き込み REST (`page-edit-for-ai`)。** Personal Access Token が要る (research §4)。PAT はスコープが無くアカウント全体に効くので、利用者に発行させて UserScript に渡させたくない
- **最上部に置く。** 決定 2

## 帰結

- **UserScript が利用者のページを書き換える初めての機能になる。** 貼ったとき (初回と、利用者が消した後) だけ、そのページが更新順の先頭に来て、通知が飛びうる
- 公開プロジェクトでは、プロフィールページを見る誰にでもカードの図が見え、**図の URL から草と活動の概観も開ける** (同じ publicId。ADR-0021 決定 6・ADR-0024 決定 4)。
  JSON の URL は作れない (ADR-0020)。プライバシーポリシーの「共有される範囲」を改訂した
- 消しても貼り直されるので、図を出したくない人は UserScript を外すしかない。設定で止める手段は段階 10 では作らない
- **commit が実際に受理されるか、`room:join` が要らないか、サーバがメタデータを計算し直すか、`disableRealtimeCollaboration` のプロジェクト (別の REST で保存する)、
  Chrome 以外は未確認** (research §7)。UserScript の PR で作者の捨てプロジェクトに送って確かめ、結果を PR と research に記録する
- 本体の WebSocket のプロトコルは公開の API ではない。変わったら貼れなくなるだけで、草の記録と送信には影響しない
