# ADR-0018 管理は cosense-grass のページに集約し、Cosense 側はそのブラウザでしかできないことだけにする

**2026-09-15、Issue #88。ADR-0017 の発展。**

## 文脈

段階 8 (#79) は「設定はすべて Cosense のダイアログに載せる」前提で作った。その結果:

- 受信方向の無い CSP (ADR-0001・0003) を迂回するために、**破壊的な操作まで画像ビーコンで送る**ことになった
  (`/v1/revoke.gif`・`/v1/delete.gif`)。どちらも経路ごとに取り決め・検証・応答の幅・テストを抱える
- **端末の一覧だけはどうやっても載せられない**ので、ADR-0017 で `/auth/devices` を別に用意した。
  設定の置き場が 2 つに割れている
- 全削除が**端末の鍵の署名だけでできる**。鍵は `extractable: false` で取り出せないが、
  「そのブラウザを触れる人が全データを消せる」ことに変わりはない

## 決定

**管理は `grass.soui.dev` のページに集約する。** Cosense の「草の設定」に残すのは、
**そのブラウザでしかできないこと**だけにする。

| Cosense (草の設定) | ページ |
|---|---|
| サインインして端末を登録 (鍵はそのブラウザにしか作れない) | 登録済み端末の一覧と失効 |
| read 計上の on/off (localStorage の設定) | 合算の共有 URL |
| この端末の切り離し (ローカルの鍵も一緒に消す) | **全データの削除** |
| このブラウザの記録の削除 (localStorage) | プライバシーポリシー |

ページは `/` (トップ)・`/account` (管理)・`/privacy` (ポリシー) の 3 枚。
`/auth/devices` は `/account` に改名して引き継ぐ。

## 理由

- **ページ側には CSP の制約が無い。** 一覧も削除も HTML と form だけで書ける。
  迂回のための経路 (`/v1/delete.gif`) を 1 本まるごと畳める
- **破壊的な操作に Google サインインを必須にできる。** 端末の鍵だけでは全削除できなくなり、守りはむしろ強くなる
- **置き場が 1 つになる。** 「設定は Cosense、でも一覧だけはページ」という分かれ方が消える
- Cosense に残るものは、どれも**サーバからは触れない**もの (IndexedDB の鍵・localStorage の記録と設定)。
  基準が「実装の都合」ではなく「その情報がどこにあるか」になる

## 帰結

- **`/v1/delete.gif`・`src/worker/admin.ts`・`src/shared/purge.ts` を撤去する** (PR #86 の大半の巻き戻し)。
  `/v1/revoke.gif` は**残す** — この端末の切り離しはローカルの鍵も一緒に消すので、UserScript から送る意味がある
- **全削除ではサーバのデータだけが消える。** ブラウザに残る記録は Cosense 側の「このブラウザの記録を消す」で消す。
  ページからは消せないので、削除後の画面でそう案内する
- **戻り先を cookie に入れる。** `/auth/start?to=account` の戻り先は `auth-cookie.ts` の payload に
  1 バイトの `mode` として入れて署名する (`COOKIE_VERSION` を 2 に上げた)。クエリで持ち回すと、
  callback の URL を作り替えるだけで戻り先を変えられる。**`mode=account` では登録トークンを発行しない**
  (端末を登録するのは Cosense からだけ)
- **プロジェクト別の共有 URL はページに出せない。** サーバはプロジェクト名を持たない (ADR-0007)。
  名前付きの一覧は Cosense の「草を見る」に残る
- `/` と `/privacy` を配信することで、**Google の同意画面が要求するプライバシーポリシーの公開先**も満たす
  (roadmap の「外部に用意するもの」に未完で残っていた)
