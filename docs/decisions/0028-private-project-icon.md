# ADR-0028 非公開プロジェクトのアイコンは、UserScript が渡す Gyazo の画像 ID で取る

**2026-10-08、Issue #234。** ADR-0024 決定 5 を改訂する。

## 文脈

- 図の名前の行に埋め込むアイコンは、Worker が `https://scrapbox.io/api/pages/<l>/<u>/icon` を**認証なしで**引いて取る (ADR-0024 決定 5)。
  **非公開プロジェクトでは取れず、名前だけになる** (ADR-0024 は「取れなければ名前だけ」と割り切っていた)
- **実測 (2026-10-08。research §4)**: 自分の非公開プロジェクト 6 件で、未認証の `/icon` は **6 件とも 401**。
  ページの `image` は **6 件とも `https://gyazo.com/<32 桁 hex>/raw`** で、その Gyazo は Worker と同じ手順で**未認証でも取れた** (200 `image/jpeg` 2.4KB)
- Worker に Cosense の認証 (Cookie・トークン) を持たせることはしない。ログインしたブラウザで動くのは UserScript だけで、そのページの `image` を読める
- UserScript から Worker への経路は、CSP の `img-src *` を通る画像 GET だけ (ADR-0001)。図の URL のクエリ (`l` / `u`。ADR-0007) が、すでに名前を渡している

## 決定

### 1. UserScript が Gyazo の画像 ID だけを `?i=` で渡し、Worker はそれで取る

- UserScript が `/api/pages/<project>/<user>` (同一オリジン・認証付き。`connect-src 'self'`) の `image` を読み、`https://gyazo.com/<id>/…` の `<id>` (32 桁の小文字の 16 進数) を図の URL の `i=` に添える
- Worker は **ID から `https://gyazo.com/<id>/max_size/64` を自分で組み立てて取る。渡された URL は取りに行かない。** 任意の URL を取らせる口を作らない
  (SSRF の面が増えない)。転送を辿る先の許可リスト・種類 (png / jpeg / gif / webp)・大きさの上限は ADR-0024 決定 5 のまま
- 取れなければ従来の `/icon` に落ちる。画像が消された公開プロジェクトでは、今の画像が出る
- `i=` は **`l=` と `u=` が付くときだけ付ける**。Worker がアイコンを描くのは名前の行だけで、取りに行くのも `l` と `u` がそろうときだけ (合算は取らない)

### 2. Gyazo 以外は渡さない

- Cosense のファイル (`scrapbox.io/files/…`)・外部 URL・YouTube のサムネは `i=` に載せず、Worker は従来どおり `/icon` を引く。**非公開プロジェクトでこれらのアイコンは出ないまま**
- 実測では、非公開プロジェクトの `image` は 6 件とも Gyazo だった。Cosense のファイルが非公開プロジェクトで未認証で取れるかは確かめていない

### 3. キャッシュの鍵は Gyazo の ID 単位で、(project, user) の鍵と別にする

- 結果は失敗も含めて Cache API に置く (成功 1 日・失敗 1 時間。D1 には保存しない) のは ADR-0024 のまま
- **ID の鍵を (project, user) の鍵と分ける。** 同じ鍵にすると、先に `i=` の無い要求 (古い版の UserScript が貼った行など) で失敗が 1 時間記憶され、
  `i=` 付きの要求が引きずられて出ない。ID の鍵は別のホスト名 (`card-icon-gyazo.invalid`) に置き、project 名が `gyazo` で user 名が ID の形のときにも、(project, user) の鍵とぶつからない

### 4. UserScript が `i=` を付ける場所は 3 つ

- **草のダイアログの図**: プロジェクト別の図は、**最初の読み込みの前に** ID の取得を待つ (待つ上限は 3 秒。同一オリジンの GET なので普段は一瞬)。
  取れなければ `i=` 無しで読む。合算 (project が無い) は待たない。取得はプロジェクトごとにそのページの読み込みの間だけ覚える
- **コピーする図の URL と、Cosense に貼る行**: 分かった ID を同じように入れる (貼った先でもアイコンが出るように)
- **プロフィールページに貼るカードの行**: 追加の取得はせず、**今読んだページの `image`** から作る (ADR-0025)。読み直したページの `image` で作り直す

## 却下した案

- **画像の URL をそのまま渡す。** Worker が任意の URL を取りに行く口になり、許可リストの検査だけに頼ることになる。ID なら URL が短く、取る先は Worker が決められる
- **`data:` の URI を URL に載せる。** 64px の画像でも数 KB になり、Cosense に貼る行 (`[…]` の画像の記法) が長すぎて壊れる
- **送信の経路でアイコンを送り、D1 に保存する。** ADR-0024 の「D1 には保存しない」を覆し、プライバシーポリシーも変わる
- **Google のアカウントの写真を使う。** ADR-0024 で却下済み (`profile` のスコープと保存が要り、顔が公開される)
- **Worker に Cosense の認証を持たせる。** 秘密の置き場と失効の手当てが増え、他人の非公開プロジェクトのアイコンを引く道具になる

## 帰結

- **図の URL を受け取った人に、アイコンの Gyazo の画像 ID が分かる。** Gyazo は URL を知っていれば誰でも開けるので、元の大きさの画像が見られる。
  図に埋め込む 64px の分はすでに見えているので、増えるのは元画像の ID だけ。**プライバシーポリシーに書く** (保存しない・見せたくなければ `i=` を削る)
- **すでにページへ貼ってある行は `i=` を持たない。** UserScript は行を書き換えず挿入だけ (ADR-0025 決定 3)。非公開プロジェクトで取り直すには、その行を消す
  (次に開いたとき `i=` 付きで貼り直される。ADR-0025)
- 貼った後でアイコンを替えると、行の ID は古いまま。古い画像が残るか、消されていれば `/icon` に落ちる
- 図を返す応答の ETag は本文の SHA-256 なので、`i=` で本文が変われば変わる (ADR-0015 決定 2)。デモは `i=` を無視する (固定の画像)
- 配布ページへ貼るまで (`npm run paste`)、UserScript の変更は利用者に届かない
