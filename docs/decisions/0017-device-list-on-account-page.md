# ADR-0017 端末の一覧は Worker のサインイン済みページで見せる

**2026-09-15、段階 8 (Issue #79)。**

## 文脈

design §9 の設定 UI は「登録済みデバイスの一覧と失効」を挙げているが、**UserScript はサーバの `keys` を読めない。**
Cosense の CSP は `connect-src` が許可リストで、`fetch` も `sendBeacon` も使えない (ADR-0001)。
送信は `img-src *` を通る画像 GET ビーコンで、**受信方向が存在しない** (ADR-0003)。

Issue #79 は 3 つの案を挙げていた。

1. この端末だけを出す
2. 失効させたい kid を手で入れる
3. 一覧を画像で返す (CORS 画像 + canvas でピクセルからデータを読む。ADR-0003 の「将来の選択肢」)

## 決定

**「草の設定」にはこの端末の kid と失効だけを出し、ほかの端末の一覧と失効は
Worker のサインイン済みページ `/auth/devices` で扱う。** ダイアログからはそのページへのリンクを出す。

そのために**30 分の署名付きセッション cookie `__Host-grass-session`** を足した (`src/worker/session.ts`)。
`/auth/callback` が成功したときだけ発行し、`/auth/devices` だけが読む。

## 理由

- **案 3 は受信経路を新しく作ることになる。** CORS 画像 + canvas は、ピクセルの詰め方・色空間の変換・
  Service Worker の再生成 (research §1) が全部絡む。一覧を見るためだけに、送信経路と同じ重さの仕組みを
  もう 1 本増やす価値が無い
- **案 2 は kid を人が知る手段が無い。** この端末の kid は「草の設定」で見られるが、
  失くした端末の kid はどこにも出ていない。「失くした端末を締め出す」という目的に届かない
- **案 1 だけでは、端末を失くしたときの手当てが「全データの削除」しか残らない。** 記録を捨てずに
  締め出せることは、この機能の存在意義そのもの
- Worker のページは**同一オリジンなので Cosense の CSP の外**にある。読み書きのどちらも素直にでき、
  HTML と form だけで完結する (スクリプトを 1 行も載せない)

## 帰結

- **cookie が増える。** `__Host-` / `HttpOnly` / `Secure` / `SameSite=Lax`、期限 30 分、
  HMAC の鍵は `WORKER_SECRET` から往復の cookie とも別のラベルで導く。
  中身は uid そのもので、乱数の session id にして D1 で引く形は採らない
  (書き込みの予算を使い、期限切れの掃除も要る。design §11)。**その代わり個別に失効できない**ので期限を短くした
- **POST を受ける経路が 1 つできる。** それまで Worker は GET と HEAD しか受けていなかった。
  失効のフォームだけが POST で、CSP の `form-action 'self'`・`SameSite=Lax`・
  セッションに結び付けた CSRF トークンの 3 つで守る。POST の後は 303 で GET に戻す
- **この画面には「どれがこの端末か」の印を出せない。** 自分の kid は UserScript の IndexedDB にしかない。
  登録日時を並べ、この端末の kid は「草の設定」で見られると案内する
- サインインは Cosense の「草の設定」から始めても、このページのリンクから始めても同じ。
  どちらでも cookie が付き、30 分は端末を管理できる
- **UserScript からこのページの中身は読めないまま。** リンクを開くだけで、一覧は利用者の目にしか届かない
