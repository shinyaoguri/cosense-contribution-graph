# cosense-contribution-graph

Cosense (旧 Scrapbox) の活動を GitHub のコントリビューショングラフのように可視化する。

「書いた」だけでなく「読んだ」活動も記録し、活動量を濃さ、読み書きのバランスを色相で表す
2 次元の草を描く。共有できる静的 SVG の URL を発行するので、Cosense のページにそのまま貼れる。

複数のプロジェクトに参加している場合は、**全体を集約した草**と**プロジェクトごとの草**の
両方を見られる。

**現在は設計段階で、まだ実装がない。** 設計と調査結果だけが `docs/` にある。

## 構成

成果物は 2 つ。

- **UserScript** — Cosense のユーザーページに 1 行 import させるセンサー兼ビューア
- **Cloudflare Worker + D1** — 記録と SVG 配信

アカウント登録も認証フローもない。クライアントが自分で鍵を生成し、サーバは鍵のハッシュしか持たない。
個人情報を一切持たず、どのページを読んだかも記録しない。**プロジェクト名も送らない。**
サーバが持つのは鍵でソルトしたプロジェクトのハッシュだけで、名前を知る手段がない。

## ドキュメント

読む順番はこのとおり。

| | 内容 |
|---|---|
| [docs/decisions.md](docs/decisions.md) | 設計判断の記録。なぜこの形なのか。**最初に読む** |
| [docs/design.md](docs/design.md) | 設計。アーキテクチャ、指標、配色、スキーマ、API |
| [docs/research.md](docs/research.md) | Cosense と Cloudflare の実測結果。出典と基準日付き |

`decisions.md` を先に読むのは、送信経路と指標の持ち方が素朴な設計と違うため。
Cosense の Content-Security-Policy が外部への `fetch` と `sendBeacon` を塞いでいるので、
データは画像の GET リクエストで送る。理由は ADR-0001 にある。

## 導入 (実装後の想定)

Cosense の自分のユーザーページに 1 行書く。

```
code:script.js
 import "/api/code/<配布project>/<page>/script.js"
```

外部ドメインからの import は Cosense の UserScript の仕組み上成立しないので、配布は Cosense の
公開プロジェクト経由になる。詳細は ADR-0005。

### 複数のプロジェクトで使う

**各プロジェクトの自分のページに、同じ 1 行を書く。** Cosense は自分のユーザーページの
`code:script.js` しか読まないので、プロジェクトごとの設置は避けられない。

**鍵を貼り直す必要はない。** localStorage はオリジン単位で、Cosense は全プロジェクトが
`scrapbox.io` の同一オリジンなので、2 つ目以降のプロジェクトでも同じ鍵が自動的に使われる。
集約はそれだけで成立する。

例外は Enterprise の独自ドメインを使っている場合。別オリジンになるので、そこでは設定 UI から
鍵を貼り付ける。

記録したくないプロジェクトには 1 行を書かなければよい。除外の設定項目はない。

### グラフを貼る

単体の角括弧記法を使う。

```
[https://<worker>/v1/g/<publicId>.svg]
```

二重角括弧の記法はクエリパラメータ付き URL を画像として展開しないので使わない。

共有 URL は全体用とプロジェクト別が独立に発行される。プロジェクト別の URL を誰かに渡しても、
全体の草や他のプロジェクトの草は見られない。

共有 SVG にプロジェクト名を出したい場合は、設定 UI でラベルを設定する。設定するまで名前は
サーバへ送られない。

## バージョン運用

**破壊的変更のときは配布ページを分ける。** 同一パスの中身を差し替えるのは、他人のブラウザで動く
コードを勝手に入れ替えることになる。同じページを更新してよいのはバグ修正に限る。

Worker の API も同様に `/v1/` を固定し、破壊的変更では `/v2/` へ上げる。

## 注意

- 鍵はパスワードマネージャに保管する。**Cosense のページに書かないこと。**
  共有プロジェクトでは他のメンバーに書き込み権を渡すことになる
- 鍵は送信時に URL のクエリに乗る。Cloudflare のアクセスログは Logpush を設定しない限り
  保存されないが、漏れた場合の影響は理解しておくこと。影響は自分のグラフが汚れることに限られ、
  他の人のデータには波及しない
- **読みの活動量には検証手段がない。** マウスを揺らすスクリプトで無限に稼げるので、
  プロジェクト内のランキングなど競争的な用途には使わないこと
