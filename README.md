# cosense-contribution-graph

Cosense (旧 Scrapbox) の活動を GitHub のコントリビューショングラフのように可視化する。

「書いた」だけでなく「読んだ」活動も記録し、活動量を濃さ、読み書きのバランスを色相で表す
2 次元の草を描く。共有できる静的 SVG の URL を発行するので、Cosense のページにそのまま貼れる。

複数のプロジェクトに参加している場合は、**全体を集約した草**と**プロジェクトごとの草**の
両方を見られる。複数のデバイスから使っても 1 つの草に統合される。

**現在は設計段階で、まだ実装がない。** 設計と調査結果だけが `docs/` にある。

## 構成

成果物は 2 つ。

- **UserScript** — Cosense のユーザーページに 1 行 import させるセンサー兼ビューア
- **Cloudflare Worker + D1** — 記録と SVG 配信

Worker は作者が 1 つホストして公開提供する。利用者は自分で何もデプロイしない。

## サーバに何が渡るか

**秘密鍵はデバイスから出ない。** デバイスごとに鍵ペアを作り、送信のたびに署名する。
運営者のログに流れるのは公開鍵と署名だけなので、**運営者でも利用者の草に書き込めない。**

サーバが保存するのは次のものだけ。

| 保存するもの | 形 |
|---|---|
| 利用者の識別子 | Google の `sub` を Worker 固有の秘密で HMAC した値。`sub` そのものは保存しない |
| デバイスの公開鍵 | 署名の検証に使う |
| プロジェクトの識別子 | 識別子でソルトしたハッシュ。**プロジェクト名は送らない** |
| 日ごとの活動量 | 分単位のビットマップと集計値 |

メールアドレスも氏名も保存しない。**どのページを読んだかも記録しない。**
read の記録にページ識別子を一切載せていないので、「誰がいつ何を読んだか」はサーバに存在しない。

**日ごとの集計値は削除しない。** 数年後に振り返れるようにするため。
分単位のビットマップだけ 90 日で消すが、これは作業データなので草は変わらない。
詳細は [プライバシーポリシーの草案](docs/privacy.md)。

## 導入 (実装後の想定)

Cosense の自分のユーザーページに 1 行書く。

```
code:script.js
 import "/api/code/<配布project>/<page>/script.js"
```

外部ドメインからの import は Cosense の UserScript の仕組み上成立しないので、配布は Cosense の
公開プロジェクト経由になる。詳細は ADR-0005。

そのあとページメニューの「草の設定」から **Google でサインイン**する。Cosense で使っているのと
同じ Google アカウントを選ぶ。これで誰の草かが決まる。

**記録は導入した日から始まる。** 過去の活動は遡らない。Cosense の編集履歴 API は約 30 日で
消えるので、遡っても 1 か月分しか得られず、実装コストに見合わないと判断した (ADR-0012)。

### 複数のデバイスで使う

**各デバイスで同じ Google アカウントでサインインするだけ。** 鍵のコピーも復旧コードも要らない。
デバイスごとに別の鍵ペアが作られ、同じ草に記録される。

設定画面に登録済みデバイスの一覧があり、使わなくなったデバイスは失効させられる。

**全デバイスを失ってもサインインし直せば元の草に戻る。**

### 複数のプロジェクトで使う

**各プロジェクトの自分のページに、同じ 1 行を書く。** Cosense は自分のユーザーページの
`code:script.js` しか読まないので、プロジェクトごとの設置は避けられない。
サインインは 1 回で済み、どのプロジェクトから使っても同じ草になる。

記録したくないプロジェクトには 1 行を書かなければよい。除外の設定項目はない。

### グラフを貼る

単体の角括弧記法を使う。

```
[https://<worker>/v1/g/<publicId>.svg]
```

二重角括弧の記法はクエリパラメータ付き URL を画像として展開しないので使わない。

共有 URL は全体用とプロジェクト別が独立に発行される。プロジェクト別の URL を誰かに渡しても、
全体の草や他のプロジェクトの草は見られない。**共有 URL は第三者には計算できない**ので、
貼るまでは誰にも見られない。

共有 SVG にプロジェクト名は出ない。サーバが名前を持っていないため。
どのプロジェクトの草かを示したいときは、貼る側のページに見出しを書く。

### 共有 SVG の更新は最大 1 日遅れる

無料枠で運用するため、送信はページを開いたとき・日付が変わったとき・タブを隠したときに限って
いる。**自分の草は常に最新**で、遅れるのは他人に見せる SVG だけ。

## バージョン運用

**破壊的変更のときは配布ページを分ける。** 同一パスの中身を差し替えるのは、他人のブラウザで動く
コードを勝手に入れ替えることになる。同じページを更新してよいのはバグ修正に限る。

Worker の API も同様に `/v1/` を固定し、破壊的変更では `/v2/` へ上げる。

## 運用するときに必要なもの

自分でホストする場合の前提。

- **独自ドメイン。** `workers.dev` では zone の WAF が効かないので、レート制限がかけられない
- **`WORKER_SECRET`。** 利用者の識別子を導出する鍵。**失うと全利用者の識別子が再計算できなくなる**
  ので必ずバックアップする
- **Google Cloud の OAuth クライアント。** `openid` スコープのみなら審査は不要
- **プライバシーポリシー。** Google の同意画面の要件であり、利用者に何を預けるのか示す責任もある
- **Bot Fight Mode は OFF にする。** JS 実行を要求するチャレンジは画像ビーコンを静かに壊す

書き込みの上限に達した日は記録が受け付けられず、翌日に再送される。データは失われない。

問い合わせは [Issue](https://github.com/shinyaoguri/cosense-contribution-graph/issues) で受ける。
プライバシーポリシーにも連絡先としてここを書く。

配布は専用の公開プロジェクトにバンドルを手動で貼る。自動化に必要な Personal Access Token は
スコープがなくアカウント全体にアクセスできるので、CI の Secrets には置かない。

## 注意

- **読みも書きも自己申告で、サーバに検証手段がない。** マウスを揺らすスクリプトで読みは無限に
  稼げるし、書きも Cosense と突き合わせていない。**プロジェクト内のランキングなど競争的な
  用途には使わないこと**
- 共有 URL を知る人には日ごとの活動量が見える。読み書きの内訳は本人の画面にしか出ない
- サーバが漏洩しても書き込み権と Google アカウントは守られるが、**活動のパターンは読める**。
  「毎日 23 時に活動している」といった情報は隠せない
- これはベストエフォートで運用される無料のサービスで、可用性の保証はない
